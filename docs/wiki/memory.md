# 用户偏好记忆

记忆与会话共用 `core.db`，只自动注入 `kind=preference` 的全局用户偏好。环境、设备、项目状态、路径、仓库规则、阶段性决定、模型推断和第三方引用不属于自动记忆。旧记录保留供显式查询，不自动提升为可信偏好。

## 整理与证据

根会话在 agent 模式成功结束后检查整理条件。默认至少积累 8 条直接用户消息，且距上次尝试至少 30 分钟；两个条件同时成立才调用模型。参数可配置，作用是降低成本，并非经过评测的最优数值。整理采用 `models.memory`，未设置时使用当前会话模型；plan 和子会话不触发整理。

只读取原始用户输入及根会话问答中的直接答案，不读取 assistant 输出、工具日志、展开的技能正文、导入的旧消息或子任务提示。每批最多 64 条新消息，加此前最多 16 条消息供习惯判断；文字预算有界。

模型必须返回严格 JSON，给出稳定偏好 key、分类、内容、是否明确长期偏好，以及消息 ID 和逐字引文。程序验证来源、引文和分类：明确偏好至少一条证据；隐含习惯至少三条不同用户消息一致支持。尚未过期的偏好只接受明确纠正，不以隐含推断覆盖；自然过期的偏好可按相同证据门槛重新学习，最新证据必须晚于到期时间和已有证据。分类仅语言、回复风格、交互方式、工作习惯、无障碍需求。语义判断仍由模型完成，用户可以检查和纠正。

无可采纳内容时不写偏好；格式错误不回退成自由文本。整理失败不使主任务失败，并保留重试间隔。多进程通过数据库中的尝试时间原子领取整理批次。

## 查看、纠正和遗忘

| 入口 | 用途 |
| --- | --- |
| `/memory` | 查看当前 / 全局有效记录，最多 30 条，显示 ID、类型和来源引文 |
| `/memory edit <id> <偏好>` | 用户直接纠正并提升为全局偏好；仅 agent |
| `/memory forget <id>` | 软归档，保留偏好 key 的遗忘标记，阻止同 key 自动恢复；仅 agent |
| `memory_search` | 显式搜索当前和全局记录；旧事实可能过时 |
| `/refresh-memory` | 清除当前会话注入快照，下次运行重新读取 |

不提供模型任意写记忆的工具。新偏好在下一次运行生效；单次运行内系统前缀固定，避免每轮模型请求反复改变。最多注入 32 条，每条最多 240 字符，总预算默认 2000 字符。设置 `default_ttl` 可让偏好到期：查询和注入根据 expires_at 排除它，维护不为偏好写入 archived_at；新证据可重新学习并更新期限。用户主动纠正也按当前 TTL 重新计时。主动遗忘继续写入 archived_at，阻止同 key 自动恢复；既有归档记录保持原状，不推断过去的归档原因。旧的非偏好记录仍按原规则到期归档。不删除对话原文。

`chat.memory.enabled=false` 时不初始化或调用记忆功能，保留数据库记录。记忆整理只通过消费方证据接口读取样本；[session](../../internal/session/evidence.go)负责会话表查询，记忆模块只管理自己的条目、索引和整理游标。FTS 写入或检索失败直接返回错误。

当前写入路径是整理器验证证据后保存偏好，以及用户直接纠正 / 遗忘。Store 不提供任意插入旧事实的入口；旧记录的读取、检索和到期处理继续保留。Manager 负责运行内注入和维护，整理器负责证据与采纳规则；部分纠正、遗忘和整理游标 SQL 仍直接位于这些实现中，尚未全部收敛到 Store。

偏好不是当前环境的事实来源，也不能改变 plan 限制。来源引文会保存在本地数据库，请将配置目录视为私有数据。
