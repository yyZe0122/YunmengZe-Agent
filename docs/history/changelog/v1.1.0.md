# YunmengZe Agent v1.1.0

**Stable release · 正式版**

This release improves tool-result persistence, MCP protocol handling and input limits, reduces context and streaming allocations, and makes configured model discovery consistent. It also removes the redundant `/refresh-memory` command; preference injection already refreshes automatically at the start of each run.

本版改进工具结果保存、MCP 协议处理和输入限制，减少上下文打包与流式输出的重复分配，并统一配置模型的列举方式。移除重复的 `/refresh-memory` 命令；记忆注入继续在每次运行开始时自动刷新。

## Highlights

- **Execution and persistence.** Serial tool results are saved before the next tool runs. Independent child tasks retain their parallel execution and save results in call order before subsequent tools start. A persistence failure stops later calls and records their non-execution where possible. CLI output failures cancel the active run and return the original write error. Database migrations claim their unique version inside the transaction, avoiding duplicate script execution when another process has already applied the same migration.
- **MCP reliability.** Connection startup, handshakes and shutdown no longer hold the shared connection-cache lock. Stdio and remote transports share response validation, reject missing or conflicting result/error fields, and match response IDs. RPC messages and remote JSON responses are bounded to 8 MiB; SSE data accumulation is bounded per event. When a legacy SSE stream ends, waiting calls consume an already queued matching response or return the stream error instead of waiting for the tool timeout.
- **Bounded inputs and explicit truncation.** Skill discovery limits frontmatter reads and scans skill IDs, names and descriptions. Model-cache loading uses a bounded read. File editing checks the final byte size before allocating the replacement, including newline conversion and BOM preservation. Oversized search and image responses return errors. Web extraction can use a partial page and exposes `truncated: true` when the response or extracted text exceeds its limit.
- **Context and streaming efficiency.** Context packing avoids an extra message clone and repeated full-history estimates while removing old complete turns. It preserves the system prefix, leading native-compaction state, the latest user turn and the durable transcript. Stream accumulation uses separate builders for content and thinking, including partial output on interruption.
- **Provider and model consistency.** Chat Completions reuses common bounded HTTP reads, network-error classification and Retry-After parsing while retaining its protocol-specific SSE and response-format fallback diagnostics. `ymz models` and startup snapshots share model-reference collection: main, role and provider-catalog models are deduplicated and sorted. Listing configured models does not require complete API credentials.
- **Memory command cleanup and documentation.** Remove `/refresh-memory` from the TUI and reserved command names. `/memory`, preference editing and forgetting remain available. Update the English/Chinese READMEs, wiki and outstanding-work list to match the implementation.

## Upgrade from v1.0.1

No database migration files or configuration fields are added or changed. Existing sessions and preferences remain in `core.db`. The migration executor changes concurrency handling; each migration's version record and SQL script still commit or roll back together. External tool effects and recording their results are separate operations, not a cross-system transaction.

`/refresh-memory` is no longer a built-in command. Start the next run to pick up current preferences; the injected prefix remains fixed during that run. Existing `/memory` commands continue to work. `web_extract` adds a `truncated` boolean to its extracted-page result. MCP responses with a missing or null result, or both result and error, now fail explicitly.

没有新增或修改数据库迁移文件、配置字段；已有会话和偏好继续保存在 `core.db`。迁移执行器调整并发处理，版本记录与 SQL 脚本仍一同提交或回滚。工具外部操作与结果入库不构成跨系统事务。

`/refresh-memory` 不再是内置命令，下一次运行会自动读取当前偏好，单次运行内注入前缀保持固定。`/memory` 命令继续可用。`web_extract` 的提取结果增加 `truncated` 布尔值；缺少结果、结果为 null 或同时包含结果与错误的 MCP 响应将明确报错。

Memory-cache simplification, child-session MCP connection reclamation and model-cache selection policy remain deferred decisions. See the versioned [configuration reference](https://github.com/yyZe0122/YunmengZe-Agent/blob/v1.1.0/docs/wiki/configuration.md) and [outstanding-work list](https://github.com/yyZe0122/YunmengZe-Agent/blob/v1.1.0/docs/backlog/current.md).

记忆缓存精简、子会话 MCP 连接回收和模型缓存选择策略仍待决定，详见以上版本化配置文档与待办清单。
