# YunmengZe Agent v1.0.0

**Stable release · 正式版**

YunmengZe Agent now runs as one local `ymz` process. The terminal UI and scripting CLI share the same engine and SQLite database, with two explicit modes: read-only `plan` and directly executing `agent`.

云梦泽 Agent 现在以单个本地 `ymz` 进程运行。终端界面和脚本命令直接使用同一引擎与 SQLite 数据库，仅保留只读的 `plan` 和直接执行的 `agent` 两种模式。

## Highlights

- **One executable and one database.** Run `ymz` to open the TUI or `ymz run` for scripts. Sessions, messages, compaction state and memory share `core.db`; no background daemon or HTTP Gateway is required.
- **Explicit execution modes.** Plan enforces read-only access at tool execution and passes that restriction to child sessions. Agent uses the current OS account's access without an approval or grant service. Child sessions are leaves; at most two explicitly independent tasks run concurrently, with the parent integrating their results.
- **Streaming and context management.** OpenAI Chat Completions, OpenAI Responses, Anthropic Messages and Google Gemini stream output while preserving protocol-specific reasoning and image content. Transient failures retry only before output begins. Token-based compaction also works inside long tool runs; optional Responses native compaction persists its replay window while retaining the original transcript.
- **Focused tools and integrations.** Skills, slash templates, TUI questions, web tools, images and MCP remain available. MCP stdio uses newline-delimited JSON with an 8 MiB message limit; connections are reused by session and server. File edits preserve BOM and newline style, tool output is bounded, and shell cancellation stops the process tree.
- **Preference memory and stable configuration.** Low-frequency curation extracts evidenced user preferences, supports correction and forgetting, and keeps old facts out of automatic injection. Provider configuration and secrets are captured together at startup; restart `ymz` after changes. Images use the current model when supported or an explicit vision role.
- **Simpler distribution.** GitHub Actions builds and publishes six platform archives plus SHA-256 checksums through the shared release script. Windows has a PowerShell wrapper. Homebrew and Scoop updates use an optional dedicated token. Local configs, database sidecars and generated output are excluded from Git, and contributor commands include a lint action that does not run tests.
- **Current documentation and UI fixes.** Both READMEs and the wiki describe the current implementation. Restored TUI history includes saved thinking blocks, interrupted runs clear pending thinking, and new sessions refresh workspace skill suggestions. CLI arguments are validated before the engine opens the database.

### 中文摘要

- **单程序、单数据库：** `ymz` 打开 TUI，`ymz run` 用于脚本；会话、消息、压缩状态和记忆共用 `core.db`，不再依赖后台 daemon 或 HTTP Gateway。
- **明确的执行模式：** Plan 在工具执行入口落实只读限制，子会话继承该限制；Agent 使用当前系统账户权限直接执行。子会话不能继续创建子会话，最多并行运行两个明确独立的任务，由父会话整合结果。
- **流式输出与上下文压缩：** 四种 Provider 协议支持流式输出，保留协议原生思考信息和图片内容；瞬时错误仅在尚未输出时重试。长时间工具循环也能按 token 压缩上下文，Responses 可选原生压缩并持久化回放窗口，数据库保留完整原始对话。
- **保留核心工具：** 技能、斜杠模板、TUI 提问、网页、图片和 MCP 继续可用。MCP stdio 使用逐行 JSON，单条消息上限 8 MiB，按会话和服务器复用连接。文件编辑保留 BOM 和换行格式，工具输出有大小限制，取消 shell 会终止进程树。
- **偏好记忆与配置快照：** 低频整理有证据支持的用户偏好，支持更正和遗忘；旧事实不自动注入。启动时一起快照 Provider 配置和密钥，修改后需要重启。图片使用具备能力的当前模型或显式配置的 vision 角色。
- **发版与文档：** 一键命令推送分支和标签，由 Actions 构建上传；提供 Windows 包装脚本、六平台压缩包和校验文件。Homebrew/Scoop 更新使用可选专用令牌。补齐本地数据忽略规则、无测试的 lint 入口、双语 README 和当前 Wiki，并修复历史思考显示及启动参数校验。

## Breaking changes and upgrade

1. **Stop all old processes and back up the entire configuration directory before starting v1.0.0.** The default is `~/.yunmengze` on every OS, or the directory set by `YMZ_HOME`. Include any existing `core.db-wal` and `core.db-shm` files, configuration, instructions and skills.
2. Migration 030 imports existing conversations and child history into the local session tables, retains memory and removes retired feature tables. Migrations 031 and 032 add preference evidence/curation state and native compaction storage. Released migrations 001–029 are unchanged. There is no downgrade migration; restore a backup with a compatible older program to roll back.
3. Database-opening commands, including `ymz sessions` and `ymz db check`, can apply migrations. Use `ymz config validate` to check configuration without opening the database.
4. Update old configuration against the [v1.0.0 configuration reference](https://github.com/yyZe0122/YunmengZe-Agent/blob/v1.0.0/docs/wiki/configuration.md). Remove retired chat fields, `models.speech` and `modelsPath`; unknown fields fail validation. Optional model roles are `subagent`, `compact`, `web`, `vision` and `memory`. Unknown image capability requires an explicit `supportsImages` override or a vision model.
5. Replace `run --execution-mode` with `run --mode plan|agent`. Existing Auto sessions migrate to Agent, which executes directly with OS account access. Choose Plan explicitly when read-only behavior is needed.

Removed components include `ymzd`, the Gateway, both VS Code extensions, approval/grant services, scheduling, checkpoints/undo, todos, cross-session transcript search, skill maintenance/usage tracking, dedicated Git tools, provider hot reload, OpenCode import, speech/audio transcription and video/ffmpeg integration. Release assets contain only the `ymz` executable; there are no VSIX packages or Node dependencies.

### 中文升级说明

1. **首次运行 v1.0.0 前，退出旧 daemon 及所有使用同一配置目录的进程，备份整个配置目录。** 默认目录为 `~/.yunmengze`，也可由 `YMZ_HOME` 指定；备份应包含存在的数据库 WAL/SHM 文件、配置、规则和技能。
2. 迁移 030 导入旧会话与子会话历史、保留记忆，并删除已移除功能的表；031、032 分别增加偏好证据/整理状态和原生压缩存储。已发布迁移 001–029 保持不变。没有降级迁移，需要回退时使用备份及与其兼容的旧程序。
3. `ymz sessions`、`ymz db check` 等打开数据库的命令也可能触发迁移；仅检查配置请使用 `ymz config validate`。
4. 按 [v1.0.0 配置参考](https://github.com/yyZe0122/YunmengZe-Agent/blob/v1.0.0/docs/wiki/configuration.md)更新配置，移除过时的 chat 字段、`models.speech` 和 `modelsPath`。未知字段会校验失败；配置或密钥修改后重启程序。
5. `run --execution-mode` 改为 `run --mode plan|agent`。旧 Auto 会话迁移为 Agent，会使用当前系统账户权限直接执行；需要只读行为时明确选择 Plan。

本版移除 `ymzd`、Gateway、两个 VS Code 扩展、审批和授权服务、定时任务、检查点/撤销、待办、跨会话全文检索、技能维护与使用统计、专用 Git 工具、Provider 热更新、OpenCode 导入及音频/视频处理。发布包只提供 `ymz` 可执行文件，不含 VSIX 或 Node 依赖。
